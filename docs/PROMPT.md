## 1. 메인 요청

# Claude Opus 5.5 — 고품질 2D 아케이드 런앤건 게임 제작

사용 가능한 개발 도구를 활용해 **Metal Slug 계열에서 느낄 수 있는 속도감, 과장된 액션, 풍부한 애니메이션, 파괴와 폭발, 강한 게임 필을 가진 오리지널 2D 횡스크롤 런앤건 게임**을 실제 제작하라.

기존 작품을 그대로 복제하는 것이 아니라, 해당 장르가 재미있는 이유를 분석해 새로운 세계관·캐릭터·적·스테이지·무기·보스를 독창적으로 설계한다.

목표는 기능 데모나 프로토타입이 아니라 **짧더라도 처음부터 끝까지 플레이할 수 있고 상용 게임의 한 스테이지처럼 느껴지는 완성된 vertical slice**다.

---

## 핵심 방향

게임은 이해하기 쉽고 조작은 즉각적이어야 한다.

플레이어가 처음 플레이하더라도 별도 설명 없이 빠르게

- 이동

- 점프

- 사격

- 회피

- 무기 활용

- 환경 파괴

를 이해할 수 있게 한다.

복잡한 시스템을 많이 넣기보다 **움직이고 쏘고 맞히고 터뜨리는 기본 행동 자체가 재미있게 느껴지는 것**을 우선한다.

특히 다음 요소를 중요하게 다룬다.

- 즉각적이고 정밀한 조작

- 개성 있는 무기와 공격

- 풍부하고 과장된 캐릭터 애니메이션

- 명확한 적 피격 및 사망 반응

- 만족스러운 폭발과 환경 파괴

- 화면 전체가 행동에 반응하는 게임 필과 Juice

- 다양한 전투 상황과 적 조합

- 계속 새로운 상황이 등장하는 스테이지 구성

- 기억에 남는 세트피스

- 강한 클라이맥스와 보스전

단순히 이펙트를 많이 뿌리는 것으로 게임 필을 대신하지 않는다.

입력 → 행동 → 충돌 → 반응 → 시청각 피드백이 하나의 흐름으로 연결되어야 한다.

---

## 아트와 연출

전체적으로 **고품질 수작업 느낌의 2D 픽셀 아트 게임**을 지향한다.

그래픽은 플레이 가독성을 해치지 않으면서 풍부한 디테일과 애니메이션을 가진다.

캐릭터와 적은 단순히 위치만 이동하는 sprite가 아니라 행동 전후의 anticipation, impact, recoil, follow-through 같은 움직임을 활용해 살아 있는 것처럼 보여야 한다.

환경 역시 정적인 배경으로 끝내지 말고 게임 상황에 맞게 반응하도록 한다.

폭발, 파괴, 연기, 잔해, 작은 환경 애니메이션, 화면 반응 등을 적절히 활용하되 항상 가독성과 플레이 감각을 우선한다.

Metal Slug의 시각적 자산이나 캐릭터를 재현하지 말고 **애니메이션 밀도와 화면 반응성이라는 디자인 원리만 참고한다.**

---

## 게임 구성

게임의 정확한 세계관과 스테이지 구성은 직접 결정한다.

다만 플레이가 단순히 평지를 오른쪽으로 걸으며 같은 적을 반복해서 잡는 구조가 되지 않게 한다.

전투 밀도와 공간 구조, 적 조합, 환경 변화, 잠깐의 휴식, 예상 밖의 사건을 이용해 자연스럽게 리듬을 만든다.

게임이 진행될수록 상황과 스케일이 점진적으로 커지고 마지막에는 확실한 클라이맥스가 있어야 한다.

필요하다면 다음과 같은 요소를 자유롭게 도입할 수 있다.

- 특수 무기

- 탑승 장비

- 구출 또는 보너스 요소

- 파괴 가능한 구조물

- 환경 기믹

- 중간 보스

- 추격전

- 이동형 전투

- 숨겨진 요소

단, 넣는 것이 게임을 실제로 더 재미있게 만들 때만 사용한다.

기능 개수를 채우기 위한 요소는 만들지 않는다.

---

## 전투와 적

각 적은 단순히 체력과 공격력만 다른 복제품이 되지 않아야 한다.

서로 다른 행동과 위협을 조합해 플레이어가 순간적으로 이동하고 목표 우선순위를 판단하게 만든다.

적 공격은 읽을 수 있어야 하며 피격이 불합리하게 느껴지지 않도록 한다.

플레이어 공격에 맞은 적은 공격 종류와 상황에 적합한 반응을 보여준다.

게임의 재미는 적 숫자를 무작정 늘리는 것이 아니라 **좋은 적 조합과 반응성**에서 만든다.

---

## 게임 필

이 프로젝트에서 가장 중요한 품질 기준 중 하나다.

총을 쏘거나 적을 맞히거나 무언가가 폭발했을 때 화면과 사운드가 즉각적으로 반응해야 한다.

필요하면 다음 기법들을 선택적으로 활용한다.

- recoil

- hit-stop

- screen shake

- impact frame

- muzzle flash

- particles

- debris

- knockback

- animation overshoot

- secondary motion

- short flash

- sound variation

- camera reaction

하지만 모든 상황에 같은 강도로 적용하지 않는다.

작은 공격과 강한 공격, 일반 적과 보스, 작은 폭발과 대형 파괴 사이에 명확한 강약을 만든다.

**효과량보다 타이밍과 대비가 중요하다.**

---

## 보스

게임의 마지막에는 지금까지 익힌 이동과 전투를 활용하게 만드는 인상적인 보스전을 만든다.

단순히 체력만 높은 일반 적처럼 만들지 않는다.

공격은 시각적으로 읽을 수 있어야 하고, 플레이어에게 이동과 판단을 요구하며, 전투가 진행되면서 상황 또는 보스 상태가 변화하는 것이 좋다.

보스의 외형이나 전장이 실제 피해에 따라 변화한다면 적극적으로 활용한다.

최종 격파는 게임 전체에서 가장 강한 보상감을 주는 순간이어야 한다.

---

## 개발 방식

먼저 현재 프로젝트와 사용 가능한 도구를 조사한다.

새 프로젝트라면 이 게임에 적합한 기술 스택을 스스로 결정한다. 웹 기반 구현이 적합하다면 TypeScript + Phaser 또는 동등한 기술을 우선 고려한다.

처음부터 콘텐츠를 많이 만들지 않는다.

먼저 작은 playable slice를 만들어

**이동 → 사격 → 적 피격 → 적 사망 → 폭발/파괴**

만으로도 재미가 있는지 확인한다.

기본 액션이 재미없다면 콘텐츠를 늘리지 말고 먼저 조작감, 애니메이션, 피드백과 전투를 개선한다.

이후 실제 플레이 결과를 기준으로 게임을 확장한다.

개발 과정에서는 가능한 범위에서 직접:

- 실행

- 플레이

- 화면 확인

- 오류 확인

- 수정

- 재실행

을 반복한다.

코드만 읽고 게임이 재미있다고 판단하지 않는다.

## 모델 자율성

세부 설계는 Claude Opus 5.5의 판단을 적극적으로 활용한다.

다음은 고정하지 않는다.

- 세계관

- 주인공

- 적 디자인

- 스테이지 테마

- 무기 종류와 개수

- 보스 형태

- 정확한 플레이 시간

- 맵 구조

- 애니메이션 프레임 수

- 수치 밸런스

- 시각 효과 구현법

- 세트피스 종류

- 사운드 방향

- 기술적 구현 세부사항

현재 결과물을 직접 관찰하고 더 좋은 해결책을 발견했다면 처음 계획보다 그쪽을 우선할 수 있다.

이 프롬프트의 예시는 요구사항 목록이 아니라 **의도와 품질 기준을 설명하기 위한 참고사항**이다.

필요 없는 기능은 과감히 생략하고, 게임에 도움이 되는 아이디어는 스스로 추가한다.

## 품질 기준

다음과 같은 전형적인 AI 프로토타입 느낌을 피한다.

- 캐릭터가 미끄러지듯 이동함

- 공격 애니메이션과 실제 공격이 따로 놈

- 적이 맞아도 반응하지 않음

- 무기가 숫자만 다르고 체감은 동일함

- 적 종류는 많지만 행동은 비슷함

- 파티클만 많고 타격감은 없음

- 긴 평지에 적만 반복 배치됨

- 배경은 화려하지만 플레이가 안 읽힘

- 보스가 큰 HP통에 불과함

- 콘텐츠는 많지만 첫 30초부터 재미없음

반대로 성공적인 결과는 **스크린샷보다 실제 움직이는 화면에서 더 좋아 보여야 한다.**

플레이어가 컨트롤을 시작하자마자 움직임과 사격에서 만족감을 느끼고, 적과 환경이 그 행동에 적극적으로 반응해야 한다.

## 검증

게임을 실제 실행해서 처음부터 끝까지 플레이 가능한지 확인한다.

최소한 다음은 검증한다.

- 핵심 조작

- 충돌과 전투

- 적 AI

- 사망 및 재시작

- 스테이지 진행

- 보스전

- 클리어

- 주요 애니메이션

- 화면 가독성

- 성능

- production build

화면을 직접 확인할 수 있는 도구가 있다면 사용한다.

첫 결과에서 끝내지 말고 플레이하면서 발견한 가장 큰 문제들을 수정한 뒤 다시 검증한다.

테스트하지 않은 것은 테스트했다고 기록하지 않는다.

## 완료 기준

최종 결과는 다음 조건을 충족해야 한다.

- 처음부터 끝까지 플레이 가능하다.

- 독립적인 오리지널 게임으로 보인다.

- 핵심 전투가 실제로 재미있다.

- 이동과 사격의 반응성이 좋다.

- 적과 환경이 플레이어 행동에 풍부하게 반응한다.

- 애니메이션과 시청각 피드백이 게임플레이와 자연스럽게 연결된다.

- 스테이지 진행 중 상황 변화가 충분하다.

- 게임 후반이 초반보다 확실히 강렬하다.

- 보스전과 명확한 클리어가 존재한다.

- 치명적인 오류 없이 production build가 성공한다.

- 최종 화면이 단순한 개발 프로토타입처럼 보이지 않는다.

기능 요구사항을 모두 체크하는 것보다 **실제로 플레이했을 때 재미와 완성도가 있는 것**을 우선한다.

필요하다면 계획을 수정해서라도 이 기준을 만족시켜라.

최종 목표는:

> **Metal Slug가 왜 뛰어난 아케이드 런앤건 게임인지 그 원리를 이해한 뒤, 이를 모방이 아닌 새로운 게임으로 재해석하여 짧지만 밀도 높고 손맛 좋은 오리지널 게임을 완성하는 것.**

작업이 끝나면 구현 내용, 조작법, 주요 설계 결정, 실제 검증 결과, 알려진 문제와 실행 방법만 간결하게 정리한다.

## 2. 추가 요청 (에셋 도구)

추가로 필요에 따라 fish 를 사용한 TTS 음성 생성 및 codex cli 를 활용한 적절한 이미지 생성도 가능하지만 적절하게 사용하것. 이미지는 가능한 경우 애니메이션에는 사용하지말고 직접 제작.

https://fish.audio/ko/app/ 를 활용하여 음성을 교체해봐, 임시 API 키는 `sk-fish-****(보관본에서 가림)` 임.
사용 예시는 이고 적절한 목소리를 활용해봐.

```powershell
$env:FISH_API_KEY = "여기에_API_KEY"
curl.exe -X POST "https://api.fish.audio/v1/tts" -H "Authorization: Bearer $env:FISH_API_KEY"
-H "Content-Type: application/json" -H "model: s2.1-pro-free"
--data-raw '{"text":"Hello! This is a Fish Audio API test.","format":"mp3"}' `
--output fish-test.mp3
Start-Process .\fish-test.mp3
```
