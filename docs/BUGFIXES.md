# RIVET RIOT 버그 수정 결과

검증일: 2026-09-30 (한국 시간). `HANDOVER.md`의 여섯 항목을 이어서 수정하고, 개발 서버와 프로덕션 빌드에서 검증했다.

## 수정 내역

| 항목 | 원인과 수정 | 확인 결과 |
|---|---|---|
| 1. 타이틀 야자수 흔들림 | 소수점 카메라 오프셋과 잎의 굽힘 방향 전환이 흔들림을 키웠다. 기존 수정인 화면 좌표 고정, 고정된 굽힘 방향, 바깥쪽 잎의 느린 움직임을 유지했다. | 타이틀 배경의 잎 픽셀만 측정: 프레임당 평균 변경 1px, 최대 11px. |
| 2. 카메라 급이동 | 기존의 속도·가속도 제한과 `cutCamera()`를 유지했다. 추가로 부두에서 카메라가 5300에 무한히 가까워지기만 해 보스 시작 조건 `화면 오른쪽 >= 5684`를 만족하지 못하는 문제를 발견했다. 목표와 속도가 모두 0.01 미만이면 정확히 목표에 정착시켰다. | 페이드 제외 6px 초과 이동 0건. 최종 보스 등장·격파·결과 화면까지 진행. |
| 3. 공격 표시 불명확 | 기존 `danger.ts`의 착탄 지점, 위험 높이, 조준선, 경고 배지를 유지했다. 적·벙커·전차·레일 카트·건십·보스의 호출 지점을 확인했다. | 전체 플레이에 렌더링 오류 없음. 건십의 위험 구간과 안전 간격, 보스의 휩쓸기·착탄 경고를 캡처로 확인. 모든 공격의 회피 난이도를 사람이 평가한 것은 아니다. |
| 4. 사망 스카프 | 스카프는 서 있는 목 좌표를 사용하지만 사망 몸체는 회전했다. 사망 시 몸체와 동일한 좌우 반전·회전·착지 오프셋으로 목 앵커를 계산하고, 스카프 끝점의 지면 관통을 막았다. | 오른쪽: 앵커 `[-2,-23] → [-11,-1]`, 끝점 `[-11,-14] → [-7,-1]`. 왼쪽 앵커 `[11,-1]`. 양쪽 사망 애니메이션 캡처와 지면 관통 검사 통과. 좌표는 발 기준. |
| 5. 적 갑작스러운 등장 | 기존의 사전 배치, 문 열기, 건십 병력 출처 표시를 유지했다. 벙커 출입 병력이 벽에 겹쳐 충돌 처리로 반대편에 밀려나는 실제 진행 정체를 추가 수정했다. 육교 강하병은 현재 육교 위치와 상판 높이에서 출발하게 하고 `bridge` 출처를 붙였다. | 출처 없는 화면 내 생성 0건. 문·탈출·육교·건십 출입 15건은 별도 집계. 벙커 전투가 종료되고 다음 구간으로 진행. |
| 6. 사망 음성 | 기존 클립이 `Oh!`로 전사됐다. 같은 HERO 보이스로 `[screaming] [shouting] Nooooo!`, 속도 0.9를 생성했다. | 새 `hero_die.mp3` 1.044898초, 전사 `No!`. 실제 `Player.hurt()` 경로에서 클립 로드·재생 1회·오디오 신호 확인(RMS 약 0.139). `public`과 `dist` 파일 SHA-256 일치. 주관적인 비명 연기·자연스러움의 청감 평가는 별도로 필요하다. |

API 키는 사용자 환경변수에서 자식 프로세스 환경으로만 전달했다. 소스·문서·로그에 저장하지 않았다. 원시 재생성 결과는 기존 스크립트대로 `art/voice_raw/hero_die.mp3`에 반영했다.

봇은 기존 입력·전투 경로를 사용했다. 전체 클리어 검사는 무적 옵션을 사용하며, 무적은 난이도나 생존 가능성을 입증하지 않는다. 보스 HP나 스테이지 이벤트를 강제로 바꾸지 않았다. 전투와 드롭에 난수가 있어 실행 프레임과 출입 건수는 달라질 수 있다.

### 검증 도구 보강

- `play.mjs`: 시나리오 예외와 브라우저 오류에 실패 종료 코드를 반환한다.
- `full`: 정체나 제한 프레임 내 미클리어를 실패로 처리한다. 정체 키의 잘못된 `st.en` 참조를 `st.enemies`로 수정했다.
- `flow`: 컨티뉴 수락 분기를 실제로 실행하고 상태·목숨을 검사한다.
- `diag`: 타이틀 로고/구름/화면 밖 좌표를 제외해 잎 움직임을 측정하고, 출처 있는 출입과 문맥 없는 생성을 따로 출력한다. 전체 플레이와 같은 9분의 시뮬레이션 예산을 사용한다.
- `deathScarf`, `deathVoice`: 실제 사망 경로에서 위치와 오디오 출력을 검사한다.

기존 야자수 수치에는 로고 등 다른 움직임이 섞여 있었고 수정 전 수치가 인수인계 문서에 없으므로, 감소율을 산출하지 않았다. 출입 출처 태그는 문·육교·차량·탈출 구현과 함께 확인했으며, 단순히 태그만 붙여 생성을 숨기지 않았다.
